# DSH 快速仿真执行约束

## 适用范围

本约束用于已经由上游研究者确定物理方案、参数律和 runner 的批量仿真任务。DSH 负责受限执行、记录和轻量验收，不负责改变热源模型、求解器、材料卡、蒸发卡或优化策略。

## 1. 任务输入必须明确

每次任务必须给出：

- 唯一的绝对 `cwd`；
- 唯一的新输出目录；
- 允许读取的文件白名单；
- 允许写入的文件白名单或目录；
- 已确定的参数公式和候选表；
- 指定 runner、工况、网格、时间步、后处理脚本；
- 验收命令和停止条件。

没有明确 `cwd`、输出目录或 runner 时，只报告缺失项，不自行扫描目录寻找答案。

## 2. 执行模式

任务必须按四个独立模式运行；完成一个模式后立即返回状态，不把四个模式合并成长回合。

### A. Preflight

- 使用 `reasoning=off`。
- 最多读取 3 个文件或执行 3 条命令，目标是检查输入存在、runner 可导入、输出目录可写、参数公式回读一致。
- 不递归扫描项目，不读取历史报告、训练集、NPZ、VTK、PNG 或完整求解器源码。
- 禁止 `todo_write`、长计划、物理推导和额外方案比较。
- 在 30 秒内写出 `selfcheck_<phase>.json` 并返回。
- 自检失败立即停止；不得擅自修改物理公式或输入文件。

### B. Solve

- 只调用上游指定的现成 runner，不重新实现求解器，不搜索替代 runner。
- 每个工况使用独立子进程和独立输出目录；已完成工况不得重跑。
- 并行度必须由上游明确指定。GPU 默认 `MAX_WORKERS=1`；CPU 粗扫只有在上游批准时才并行。
- 禁止读取历史结果目录，禁止在求解完成后重新遍历大文件。
- runner 必须在每个样本完成时写出 `metrics_fast.json`，至少包含：

  `case_id, status, W_um, D_um, RMS_um, Tmax_K, energy_residual_max, backend, steps, parameters, solver_exit_code, wall_s`

- 不得用长时间阻塞等待。以下两种形式一律禁止：
  - 工作区命令中的 `Start-Sleep` / `sleep`；
  - `job_output` 带 `wait=true` 且 `timeout_ms > 60000`（超过 1 分钟即违规）。
- 正确做法：
  - 短查用 `job_output` 且 `wait=false`，或 `wait=true` 且 `timeout_ms <= 15000`；
  - 长任务不在执行侧阻塞等待：立即返回当前状态，由上游通过桥的 `dsh_status` 查询进度；
  - 或只读任务指定的进度文件（一个小 JSON），不得递归扫描目录。
- 求解阶段不生成长报告，只返回样本状态、真实退出码和输出路径。

### C. Postprocess

- 只有在求解阶段全部完成后才能启动。
- 只读取当前批次的 `metrics_fast.json`、`progress.json`、`summary_86.json`、`contract_86.json` 以及任务明确授权的固定轮廓提取脚本。
- 轮廓提取只能对当前批次的 `fields_*.npz` 执行一次；不得从头搜索提取链，不得重复计算已经写入的轻量指标。
- 生成一个 `metrics_<phase>.csv`、一个 `metrics_<phase>.json` 和一份不超过 80 行的短报告。
- 报告必须区分：求解器完整性、数值守恒、W/D/RMS 物理指标和是否允许进入 GPR/MOBO。代理预测不能作为真实求解结果。

### D. Stop

- 输出文件写完、验收命令通过后立即停止并返回。
- 不继续写解释性长文，不自动启动下一轮扫描，不自动训练 GPR/BO，不主动扩大工况范围。

## 3. 读取与写入边界

- DSH 只能访问任务白名单和指定输出目录；不得读取凭据、用户目录或整个工程。
- 同一批文件只允许一个执行者写入。发现已有用户修改、活动任务或输出目录冲突时，立即报告并停止。
- 不修改 `clean_solver.py`、材料卡、蒸发卡、历史结果和训练集，除非上游明确列入允许写入清单。
- 不能把“文件存在”或“模型自称完成”当作验收；必须检查实际 JSON、真实退出码、步数、后端和能量残差。

## 4. 推理等级与会话复用

- `reasoning=off`：机械执行、已有 runner、固定后处理。
- `reasoning=low`：只在需要少量代码适配且物理决策已给出时使用。
- `reasoning=medium` 以上：仅用于上游明确要求的方案评审，不得用于常规求解批次。
- 同一物理方案的续跑优先复用同一 session；物理方案或输出目录改变时新建 session，避免旧上下文膨胀。
- session 只保存执行上下文，不代表跨重启永久保留；每次任务仍必须给出完整白名单和停止条件。

## 5. 失败处理

- 失败时保留 traceback、真实退出码、失败样本编号和已完成样本，不覆盖结果。
- 只允许在同一输入下重试一次明确的机械故障；不得把数值失败自动改成放宽门槛或改变物理参数。
- 若指标缺失，报告“指标未提取”并停止；不要编造 W、D、RMS，也不要为了补指标重新扫描整个目录。

## 6. 默认返回格式

只返回：

1. 阶段和真实状态；
2. 完成/失败样本及真实退出码；
3. `metrics_fast` 和最终小型报告路径；
4. W、D、RMS、峰温、后端、步数、能量残差；
5. 是否满足进入下一阶段的判据；
6. 未完成事项或阻塞原因。

禁止返回与任务无关的长篇推理、历史目录清单或重复的物理背景。
